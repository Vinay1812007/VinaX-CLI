# Changelog

Milestone progress before the first npm release. Once `vinax` is published, per-release notes are
generated by changesets in `packages/cli/CHANGELOG.md`.

## Unreleased

### M4: Workflow (2026-09-23)

- **Slash commands.** `/` opens a completion menu covering `/help`, `/clear`, `/compact`,
  `/model` (with a picker), `/config`, `/permissions`, `/init`, `/memory` (opens `$EDITOR`),
  `/resume`, `/rewind`, `/status`, `/usage`, `/doctor`, `/login`, `/logout`, `/theme`, `/vim`,
  `/export`, `/bug` and `/exit`.
  - `/status` shows remaining rate limits and the OpenRouter free-tier quota.
  - `/usage` shows today's requests and tokens per provider and model, including the
    OpenRouter 50-requests-a-day `:free` cap.
- **Custom commands** live in `.vinax/commands/` and `~/.vinax/commands/`, with frontmatter:
  - `description`, `argument-hint`, `allowed-tools` and `model`
  - `$ARGUMENTS` and `$1…`
  - `` !`cmd` ``, which only runs if `allowed-tools` permits it
  - `@file` includes
  - subfolder namespaces
- **Prefixes:** `@path` fuzzy completion that attaches files and folders, `!` runs a shell
  command directly and gives the model its output, and `#` saves a note to project or personal
  memory.
- **Memory:** `~/.vinax/VINAX.md`, plus `VINAX.md`/`AGENTS.md` from the repository root down to
  the working folder, plus subfolder files when VinaX first works there, with `@imports` up to
  four levels. `/init` writes a starter `VINAX.md`.
- **Sessions:** each conversation is saved as a JSONL transcript, with checkpoint contents stored
  once per file, so rewind now works across restarts too.
  - `-c` continues the latest conversation and `-r` resumes one via a picker or by id, in both
    interactive and `-p` mode.
  - `/clear` and `/resume` switch conversations.
  - The small model writes a title after the first answer.
- **Compaction:** there is a conversation budget (`context.maxTokens`, 24K by default). At 85%,
  VinaX first drops old tool outputs (free), then has the small model write a structured summary.
  `/compact [focus]` does this on demand.
- **Vim mode** for the prompt, saved as a setting: `hjkl w b e 0 ^ $ x X D C S dd cc dw cw` and
  `i a I A o O u`.
- **`vinax doctor`** runs the same checks as `/doctor`, and exits with code 1 if any check fails.
- **Fixes:**
  - Title generation no longer spends main-model quota. It only uses the small model, with no
    fallback.
  - Enter runs commands whose only arguments are optional.
- **Deferred to M5:** `/hooks`, `/mcp` and `/agents`, with the features they manage.

### M3: Agent (2026-09-23)

- **Agent loop.** Each step streams a reply, collects tool calls, validates them with zod, checks
  permissions, runs the tools and sends the results back. It repeats until the model stops
  calling tools or `--max-turns` is reached. Read-only calls run in parallel; changes run one at
  a time.
- **Tools:** Read, Glob, Grep (ripgrep with a JS fallback), LS, Edit, MultiEdit, Write, Bash (with
  BashOutput and KillBash), TodoWrite and ExitPlanMode.
  - Search respects `.gitignore`.
  - Edit and Write refuse files that haven't been read, or that changed since they were read.
  - Bash keeps its working directory between calls, times out, runs in the background, refuses
    interactive programs, and kills the whole process tree on timeout or Esc. On Windows it uses
    Git Bash, falling back to PowerShell.
- **Two ways to call tools.** Native OpenAI-style calls come first. A model switches to the
  `<vx:call>` text protocol, which is parsed as the reply streams, when:
  - its catalog entry says it lacks tools
  - the provider rejects its call (Groq `tool_use_failed`), in which case the same model is
    retried immediately
  - it sends two malformed calls

  Validation errors are sent back to the model so it can fix its call.
- **Permissions:**
  - allow, ask and deny rules (`Bash(prefix:*)`, wildcards, gitignore-style paths,
    `domain:`, MCP patterns); deny always wins
  - a compound command is allowed only if every part matches
  - a dangerous-command detector that always asks
  - modes: default, auto-accept edits and plan
  - `--allowedTools`, `--disallowedTools`, `--permission-mode` and `--add-dir`
- **Approval prompt:**
  - the command, or a coloured diff of the edit
  - danger warnings
  - Yes, or "don't ask again" for a suggested rule (this session or this project)
  - auto-accept edits
  - No with feedback for the model
- **Plan mode:** only read-only tools are offered. The plan is shown for approval, and approving
  it can switch on auto-accept.
- **Checkpoints and rewind (Esc Esc):** restore the conversation, the files, or both, as they
  were before an earlier prompt.
- **UI:**
  - each tool call as a line plus a one-line result, with the command's live output while it
    runs
  - diffs in the transcript
  - a live task checklist
  - Ctrl+O lists every tool call with its output
- **Headless `-p`** now runs the full agent. Actions that need approval fail with a hint rather
  than blocking. `stream-json` gains `tool_use` and `tool_result` events.
- **System prompt:** new wording, including git branch and status and tool guidance.

### M2: Terminal UI (2026-09-23)

- **Interactive mode** is built with Ink 7. `vinax` starts it, and `vinax "prompt"` starts it
  with a first prompt. It needs a real terminal; in scripts, use `vinax -p`.
- **First-run setup** has four steps: theme with a live preview, provider, API keys (each checked
  live, with keys from environment variables reused), and a default model chosen from the
  provider's live catalogue. The folder trust prompt remembers its answer for the folder and
  everything inside it.
- **Welcome panel** shows the VinaX wordmark, version, folder, model and provider, plus three
  random tips.
- **Input box:**
  - multi-line editing (`\`+Enter, Shift+Enter via the kitty keyboard protocol, Option/Alt+Enter)
  - bracketed paste, with large pastes collapsed to a placeholder
  - per-project history (↑/↓) and reverse search (Ctrl+R)
  - readline-style editing keys
  - prompts typed while a reply streams are queued
- **Streaming Markdown** has its own renderer covering headings, lists, task lists, tables, block
  quotes and highlight.js code blocks. Finished blocks move into scrollback as they complete, so
  long answers don't flicker.
- **Activity indicator:** animated glyph, rotating status words, elapsed time, approximate
  tokens and `esc to interrupt`. Rate-limit waits are shown in place.
- **Footer:** mode (Shift+Tab cycles default → auto-accept edits → plan), active model, and how
  much of the context budget is used, capped by tokens-per-minute on Groq. Fallback and retry
  notices appear there too.
- **Keys:** Esc interrupts and keeps the partial answer (the model sees it was cut off). Ctrl+C
  clears the prompt, and pressing it twice within 2s exits. Ctrl+D exits. Ctrl+O shows turn
  details and live rate limits. `?` shows every shortcut.
- **Themes:** dark, light and colour-blind friendly (Okabe–Ito). `NO_COLOR` switches to a
  monochrome UI.
- **Conversations:** the core `ChatSession` keeps multi-turn history. The new `theme` setting is
  also added.
- **Fixed:** a stream cut off by an abort was treated as a finished answer, because the SDK ends
  the iteration quietly. It's now reported as interrupted.
- **Fixed:** the process could linger after exit while idle HTTP keep-alive sockets stayed open.
- **Deferred:**
  - The optional gateway login step of onboarding moves to M6, where the gateway is built.
  - The Esc Esc rewind picker moves to M3, with checkpoints.
  - `/vim` moves to M4, with slash commands.

### M1: Core (2026-09-23)

- pnpm monorepo: `packages/core` (UI-free), `packages/cli` (`vinax`), `packages/testkit`, with
  strict TypeScript, ESLint (typed, strict), Prettier, Vitest and Changesets.
- Settings: zod-validated, merged from user, project, local and CLI layers. Unknown keys produce
  warnings and invalid values produce errors that name the key. `.vinax/settings.local.json` is
  added to `.gitignore` automatically.
- API keys: environment variables first, then the OS keychain (`@napi-rs/keyring`), then a 0600
  credentials file. Keys are verified live before they're stored.
- Providers: Groq and OpenRouter through the official `openai` SDK with per-provider `baseURL`,
  streaming and usage reporting. Model catalogs come from `/models` and are cached for 24h.
  Configured models missing from a catalog are skipped with a warning.
- Rate limits: Groq and OpenRouter rate-limit headers and `retry-after` are parsed into a ledger,
  with a local requests-per-minute window. Requests that can't fit a model's tokens-per-minute
  budget are never sent to it.
- Router: the fallback chain uses a pre-flight budget check, a short wait-or-skip decision,
  exponential backoff with jitter for transient errors, and one-line fallback notices. It never
  falls back mid-stream.
- `vinax -p`: piped stdin, `--output-format text|json|stream-json`, `--model`, and meaningful
  exit codes (0/1/2/130).
- `--verbose` writes a JSON-lines debug log with API keys redacted.
- `vinax config list|get|set|unset|keys|set-key|remove-key`.
